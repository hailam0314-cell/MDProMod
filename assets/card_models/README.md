# 单张卡片模型与动态卡面方案

单张卡片已经做成一个共用几何体：所有卡片使用同一个模型，正面贴当前卡号对应的完整卡图，背面贴 MDPro 默认卡背。不需要为每张卡建立独立模型。

## 模型规格

| 项目 | 数值 |
| --- | --- |
| 卡片宽度 | 6.875 |
| 卡片长度 | 10.0 |
| 卡片厚度 | 0.06 |
| 正面比例 | 704:1024 |
| 原点 | 底面中心，Y = 0 |
| 场地放置高度 | 0.75，与决斗垫上表面齐平 |

模型只有一个长方体 `Card_Body`。顶面是动态卡面，底面是共用卡背，四个侧面是卡边纹理。模型包含以下定位点：

- `card_origin`
- `card_face_surface`
- `card_back_surface`
- `card_attack_anchor`
- `card_defense_anchor`
- `card_texture_swap`

攻击表示时，卡片长轴朝玩家前方；守备表示时，绕 Y 轴旋转 90 度。背面朝上时，可以让渲染器把共用卡背绑定到顶面，或者把模型绕 X 轴翻转 180 度，让底面露出。背面纹理的方向由渲染器按玩家视角统一处理。

## 为什么不把一万多张卡图放进资源包

一张 `704 × 1024` RGBA 纹理占用约 **2.75 MiB** 显存。若把 15,019 张全部常驻，约 **40.3 GiB**。这些数字还没有计算 mipmap 和 Minecraft 纹理图集开销，因此不能把全部卡图打包进资源包或一次性上传到显卡。

正确做法是**共用模型 + 按需纹理**：

1. 卡背、卡边、卡组和场地纹理常驻。
2. 只有当前可见且正面朝上的卡才加载卡面。
3. 卡面纹理按卡号缓存，超出上限后使用 LRU 淘汰。
4. 卡片离开场地、翻到背面或超出可视范围时释放纹理。

## 推荐缓存大小

| 缓存策略 | 单张显存 | 缓存数量 | 合计显存 |
| --- | ---: | ---: | ---: |
| 默认 176 × 256 | 0.172 MiB | 128 张 | 约 22 MiB |
| 详情 704 × 1024 | 2.75 MiB | 4 张 | 约 11 MiB |
| 旧版 352 × 512 | 0.688 MiB | 32 张 | 约 22 MiB |

默认场地和物品栏使用完整的 `176 × 256` 缓存，128 张只占约 22 MiB 显存；卡片详情界面再按需加载原始 `704 × 1024` 母版，只保留 2–4 张。这样即使场上有很多正面卡片，常态显存也能保持在几十 MiB，而不是几 GiB。

## Minecraft 1.20.1 / Forge 接入思路

建议在客户端写一个 `CardTextureCache`：

1. 卡号是键，例如 `89631139`；纹理 ID 可以是 `mdpromod:dynamic/card/89631139`。
2. 先查缓存；命中时直接返回 `ResourceLocation`。
3. 未命中时优先读取最小缓存 `card_textures_176x256_q80\<code>.jpg`；这个文件已经压缩过，直接解码即可。
4. 如果最小缓存缺少该卡号，就读取原始 `Picture/CardGenerated\<code>.jpg` 并在后台缩小；`card_textures_352x512_q85` 只是旧的部分缓存，可选。
5. 在渲染线程创建 `DynamicTexture`，调用 `TextureManager.register(location, texture)` 完成 GPU 上传。
6. 渲染卡片时用 `RenderSystem.setShaderTexture(0, location)` 绑定正面纹理。
7. 缓存超过上限时按 LRU 顺序释放；缺失或解码失败的卡号回退到共用卡背。

不要在工作线程直接上传 GPU 纹理；解码和缩放可以在工作线程完成，注册和上传必须在渲染线程执行。

卡图路径优先查找：

```text
D:\MyCardLibrary\mdpro3\Picture\CardGenerated\<card_code>.jpg
```

如果以后把导出格式改成 PNG，则同时检查 `.png`。找不到完整卡图时，正面回退到默认卡背或占位卡图，不影响决斗继续运行。

运行时的档位清单保存在：

```text
D:\MDProMod\runtime\card_texture_profiles.json
```

每个缓存目录里也有自己的 `manifest.json`，记录尺寸、质量、文件数和总大小。原始 `Picture\CardGenerated` 母版保持原样，没有被覆盖或删除。

## 手牌和卡组

主卡组、额外卡组和背面朝上的卡只需要共用卡背，不触发卡面加载。手牌如果显示在 Minecraft 物品栏中，可以选择两种方案：

- 手牌物品图标也接入 `CardTextureCache`，手牌数量少，显存压力不大。
- 物品栏只显示卡背，悬停预览或单独界面才加载正面卡图。

以后实现墓地、除外区和场地魔法时，也可以复用同一个单卡模型；只有最上面可见且正面朝上的卡需要动态卡面。
