# 提示里的「时机」说明（2026-10-15）

MD 在弹「要不要发动 / 要不要连锁」的时候会先说清时机，比如
「对方进入准备阶段，是否发动」「〈卡〉的效果发动了，是否连锁」。模组之前只有
干巴巴的「是否发动〈卡〉的效果？」，这次补上。

## 文案规则（`DuelTiming`，纯函数）

| 场景 | 例子 |
| --- | --- |
| 进入阶段 | 「对方进入准备阶段」／「自己进入战斗阶段」 |
| 连锁询问 | 「「真红眼暗钢龙」的效果发动了，是否连锁？」 |
| 发动询问 | 「对方进入准备阶段，是否发动「青眼白龙」的效果？」 |

阶段码（DP/SP/M1/BP/M2/EP，和场地控制条同一套）→ 抽卡阶段 / 准备阶段 /
主要阶段 1 / 战斗阶段 / 主要阶段 2 / 结束阶段。卡名拿不到时退化成
「有卡发动了效果」「是否发动效果？」。

## 接到哪儿

1. **连锁窗口**（`ChainChoiceScreen`）：标题下面多一行时机说明，面板宽度会按这句话
   自适应（长卡名也不会被卡图排挤出去）。句子里的"来源卡"取**连锁栈最上面那张**
   （`host.chainCodes()` 的最后一项，掩掉场地效果的 `0x80000000` 标记）。
2. **发动确认**（`DecisionScreen`，功能号 12 `SelectEffectYN`）：
   问句改成「〈谁〉进入〈阶段〉，是否发动「〈卡〉」的效果？」，用的是宿主的
   `turnPlayer()` + `phaseCode()`。
3. **阶段播报**：进入新阶段时给自己一条 action bar 提示（「对方进入准备阶段」）。
   这份状态本来就在每 tick 同步（`DuelSessionManager` 里写 `setCurrentPhase`），
   这里只是**多判一次变化**，同阶段重复同步不会重复播报。

## 没有改的部分

`SelectYesNo`(13) 的问句仍是通用的「是否确认当前操作？」——它是"是/否"型确认，
不一定和阶段有关，硬套时机反而会误导。

另外：模组里 `SelectIdleCmd`（主要阶段的可发动窗口）没有独立弹窗，
时机是靠**场地上的阶段键 + 卡片动作菜单**表达的，所以那边没有加文字；
现在靠第 3 条的阶段播报把"什么时候"说清楚。

## 修正：转阶段那次问的是"要不要发动"，不是"已经发动了"（2026-10-15 追加）

**问题**：转阶段（以及各种"可以发动效果"的时机）也会弹连锁窗口，标题下面写的是
「有卡发动了效果，是否连锁？」——可这时候**什么都还没发动**，核心问的是"要不要发动"。
那是 `chainQuestion()` 卡名解析不出来时的兜底句，被用错了场合。

**原因**：`chainTriggerName()` 取的是**连锁栈最上面那张**（`host.chainCodes()` 最后一项）。
链上还什么都没有时（第一次发动之前的那个窗口）它自然是空的，于是落到了兜底文案。

**改法**（`DuelSessionManager`）：

| 情况 | 判据 | 文案 |
| --- | --- | --- |
| 链上已经有东西，问的是"要不要接" | `host.chainCodes().length > 0` | 「「〈链顶卡〉」的效果发动了，是否连锁？」（拿不到卡名才退化成「有卡发动了效果，是否连锁？」） |
| 链上还是空的，问的是"要不要发动" | `host.chainCodes().length == 0` | 「「〈候选卡〉」的效果可以发动，是否发动？」／多张候选时「有 N 张卡可以发动效果，是否发动？」 |

候选卡名来自连锁窗口的候选清单（`host.chainChoiceCodes()`，同样掩掉场地效果的
`0x80000000`），纯函数 `DuelTiming.openQuestion(String[])` 负责挑名字/数张数。

窗口本身也跟着这次语义改了（新字段 `ChainChoice.opening`）：

| 元素 | 已接上连锁（opening=false） | 还没接上（opening=true） |
| --- | --- | --- |
| 标题 | 连锁 | 发动效果 |
| 按钮 | 连锁 / 取消 | 发动 / 不发动 |
| 强制时的角标 | 必须接 | 必须发动 |
| 卡图角上的数字（第几环） | 显示 | 不显示（那些是候选，不是环号） |

`DuelTimingTest` 新增 5 条断言（一张候选点名 / 多张只数数 / 名字为空 / 候选为空），
现在 20 条全过。
