# 卡片效果编写指南：以本地 MDPro3 核心为准

配套分析：[MDPro3 决斗规则源码分析](D:/MDProMod/docs/MDPro3决斗规则源码分析.md)。本指南适用当前本地快照，后续更换引擎需重核接口。

## 1. 一张卡需要的内容

卡号在 CDB、Lua 文件名和卡图文件名之间保持一致。CDB 的 datas 保存规则属性，texts 保存名称、效果文本和最多 16 项选项说明；`script/c<id>.lua` 注册行为。卡图不是效果实现。

数据库按列名读取，尤其不要按旧 C# SELECT 的顺序误解物理列顺序。`level` 字段携带等级与左右灵摆刻度；连接怪兽数据库的 def 字段被映射为 link_marker，不能显示为守备力。setcode 是系列/字段数据，核心实际使用 16 项 uint16 数组；从 CDB 整数展开时要符合当前 loader 约定。

新卡号需避开现有卡库、异画映射和扩展卡，预留区间应先调查并固定。异画与规则上同名卡的 alias 不可随意填写，当前 `is_alternative` 有卡号差值规则和例外。

## 2. 效果拆分

每个实际效果单独建立 Effect：

| 配置 | 含义与注意点 |
|---|---|
| CreateEffect / RegisterEffect | 建立并注册；注册后由核心按事件和范围处理 |
| SetType | 起动、任意/强制诱发、任意/强制快速、魔陷发动、永续等 |
| SetCode | 监听 EVENT，或提供某个规则属性 EFFECT；含义由类型决定 |
| SetRange | 效果有效/可发动的区域；不代表对方可以看到此卡 |
| SetProperty | 取对象、延迟、伤害步骤、伤害计算、不可无效等特性 |
| SetCondition | 事件条件；保持无操作副作用 |
| SetCost | chk=0 检查能支付；实际执行分支付费用 |
| SetTarget | chk=0 检查能发动；实际执行分选对象/登记信息，非取对象效果也可使用 |
| SetOperation | 连锁结算执行；重新检查必要关联与条件 |
| SetCategory / SetOperationInfo | 描述发动与操作信息，其他卡会依赖它们进行裁定 |
| SetCountLimit | 定义次数与共享编码；根据卡片文本选择 |
| SetReset | 临时效果的失效事件/阶段/回合/次数 |

不要因卡片“看起来相似”就完整复制属性。先区分取对象还是结算时选择、费用还是效果处理、发动无效还是效果无效、此卡一次还是同名共享一次。

## 3. 回调参数

常见签名为 `function s.cost(e,tp,eg,ep,ev,re,r,rp,chk)`；target 还可能接收 chkc。

- e：当前 Effect，`GetHandler` 取得关联卡。
- tp：该效果的处理玩家，不一定是当前回合玩家，也不一定等于事件玩家。
- eg：事件涉及的 Card Group。
- ep、ev：事件玩家与事件数值；例如 EVENT_CHAINING 的 ev 是连锁编号。
- re、r、rp：原因效果、原因位标志和原因玩家。
- chk：0 是可行性检查，实际支付费用/选择时为 1。
- chkc：用于检查对象候选的特定卡；按现有取对象脚本处理。

回调形参由具体类型/接口决定，不能把普通发动回调直接套到特殊召唤程序的 condition/value 上。

## 4. 风格模板

本地 `utility.lua` 提供 GetID，既支持 `c卡号.initial_effect` 风格，也支持 `local s,id,o=GetID()` 风格。

以下只是结构示意；不是可直接发布的一张卡：

```lua
local s,id=GetID()
function s.initial_effect(c)
    local e1=Effect.CreateEffect(c)
    e1:SetType(EFFECT_TYPE_IGNITION)
    e1:SetRange(LOCATION_MZONE)
    e1:SetCategory(CATEGORY_DRAW)
    e1:SetCountLimit(1,id)
    e1:SetTarget(s.target)
    e1:SetOperation(s.operation)
    c:RegisterEffect(e1)
end
function s.target(e,tp,eg,ep,ev,re,r,rp,chk)
    if chk==0 then return Duel.IsPlayerCanDraw(tp,1) end
    Duel.SetTargetPlayer(tp)
    Duel.SetTargetParam(1)
    Duel.SetOperationInfo(0,CATEGORY_DRAW,nil,0,tp,1)
end
function s.operation(e,tp,eg,ep,ev,re,r,rp)
    local player,count=Duel.GetChainInfo(0,CHAININFO_TARGET_PLAYER,CHAININFO_TARGET_PARAM)
    Duel.Draw(player,count,REASON_EFFECT)
end
```

是否需要 condition、费用、来源卡仍表侧存在等条件，应由具体效果文本确定，不要默认给全部结算加 `GetHandler():IsRelateToEffect`；许多效果发动后即使来源卡离场仍会结算。

## 6. 最容易出现的错误

1. **在 chk=0 时支付费用。** UI 刷新就可能多次检查，会重复扣除或触发 Action is not allowed。
2. **把费用当效果。** 灰流丽弃自身是 `REASON_COST+REASON_DISCARD`；不应写成结算时效果送墓。
3. **只根据卡号判断对象。** 对象离开再回来可能已经没有原关联。
4. **把 target 函数当作取对象标签。** 取对象需要属性和正确 API；雷击的 target 函数并不取对象。
5. **操作信息漏填或错填。** 抽卡/检索等响应卡可能因此不能发动或错误地能发动。
6. **把破坏、送墓、解放混用。** 破坏耐性、替代、送墓诱发等依赖原因与操作种类。
7. **忽略 return 数量/结果。** “然后”“若如此做”等文本需要判断前序操作是否完成，必要时 BreakEffect；不应机械加 BreakEffect。
8. **所有诱发都加 DELAY。** 会改变时点和错过时点的行为。
9. **所有快速效果都允许伤害计算。** DAMAGE_STEP 与 DAMAGE_CAL 范围不同。
10. **复制新版 SetCountLimit 参数。** 当前接口接收整数 code；table 风格不能直接照搬。
11. **遗漏临时效果 Reset。** 一回合限制可能永久残留，或离场回来仍生效。
12. **不完成正规召唤。** 相关特殊召唤应正确标记程序完成，后续苏生才符合规则。
13. **跨协程保存 Group 却未管理生命周期。** 长期保存时按 KeepAlive/DeleteGroup 等接口管理，不要保存已释放的临时组。
14. **客户端自行结算。** 多人双方状态分歧、隐藏信息泄漏和越权选择会随之出现。

## 7. 新效果最低验证清单

每张新卡至少准备：能正常发动并结算；条件不满足时不能发动；费用不足/无合法对象时不能发动；支付费用后效果被无效；发动被无效与效果被无效的区别；对象在连锁中移动；同名多副本次数限制；临时效果在指定时间失效。按类型加上材料不足、区域被封、苏生限制、伤害步骤限制等用例。

对一个新 API 或新机制，先用少量可复现卡组验证，再扩展批量卡片。记录随机种子、核心/脚本哈希、输入响应与错误日志。Lua 语法通过、脚本文件存在、initial_effect 无异常都不能代替完整效果测试。
