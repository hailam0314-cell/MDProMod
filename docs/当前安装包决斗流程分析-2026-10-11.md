# 用户提供的 MDPro3 安装包：决斗流程分析

分析对象：`D:\\MyCardLibrary\\mdpro3`，文件时间主要为 2026-09-26。本文根据 `MDPro3_Data\\Managed\\Assembly-CSharp.dll` 的反编译结果整理，反编译输出位于 `D:\\MDProMod\\analysis\\latest_decompiled`。未修改安装目录。

## 启动

`MDPro3.Boot.Start` 初始化语言并加载 `SceneMain`。`Program.Awake`/`Initialize` 初始化资源、禁限表、卡图、网络服务、Managers 和 Servants。`Program.Update` 每帧调用 `TcpHelper.PerFrameFunction`，再更新各服务对象。

## 单人 AI

`SoloSelector.StartAIForSolo` 读取 `Data/locales/<language>/bot.conf` 和 `Data/Windbot/Decks/AI_*.ydk`，构造本地服务器参数：

```text
<port> -1 5 0 F <noCheck> <noShuffle> <LP> <startHand> <drawCount> 0 0
```

随后调用 `YgoServer.StartServer`（P/Invoke 到 `MDPro3_Data/Plugins/x86_64/ygoserver.dll`），再通过 `TcpHelper.LinkStart` 连接 `127.0.0.1`。回调启动 `WindBot.Program.Main`，WindBot 作为标准 YGOPro TCP 客户端加入本地房间。

WindBot 的 `GameClient` 发送 `ExternalAddress`、`PlayerInfo`、`JoinGame`，`GameBehavior` 处理全部标准 `StocMessage`/`GameMessage`，`GameAI` 调用牌组 Executor 生成选择响应。

## 网络对局

`OnlineServant.KF_OnlineGame` 直接调用 `TcpHelper.LinkStart(ip, name, port, password, local:false)`。本地建房使用 `YgoServer.StartServer` 后连接 localhost。客户端协议为标准 YGOPro 风格 TCP：两字节 little-endian 包长度，之后是 function byte 和 payload。`Config.ClientVersion` 为 `4962`。

主要 CTOS：`Response=1`、`UpdateDeck=2`、`HandResult=3`、`TpResult=4`、`PlayerInfo=16`、`JoinGame=18`、`Surrender=20`、`Chat=22`、`ExternalAddress=23`。主要 STOS：`GameMsg=1`、`SelectHand=3`、`SelectTp=4`、`JoinGame=18`、`TypeChange=19`、`DuelStart=21`、`DuelEnd=22`。

## 决斗消息和 UI

`RoomServant.StocMessage_GameMsg` 将游戏消息加入 `OcgCore.packages`。`OcgCore.ApplyShowArrangement` 启动 `DuelBGManager` 和 `ProcessMessage`。消息依次经过 `MessageDispatcher` 的 `LogMessage`、`VoiceMessage`、`DuelMessage`。`DuelMessage` 负责将 `GameMessage` 解析为场上卡片、连锁、战斗、阶段和选择状态。

`OcgCore` 维护 `List<GameCard> cards`，卡片由 `GPS(controller, location, sequence, position)` 定位。Minecraft 版本应把这些状态作为唯一事实来源，实体和临时物品栏只是投影。

需要响应的消息包括 `SelectBattleCmd`、`SelectIdleCmd`、`SelectEffectYn`、`SelectYesNo`、`SelectOption`、`SelectCard`、`SelectChain`、`SelectPlace`、`SelectPosition`、`SelectTribute`、`SortChain`、`SelectSum` 和宣言类消息。`OcgCore.SendReturn` 最终转为 CTOS `Response`。

## 阶段按钮

`DuelBGManager.LoadAssetsAsync` 加载 `PhaseButton_c001` 并挂载 `PhaseButtonHandler`。按钮只在核心发出 `SelectIdleCmd` 或 `SelectBattleCmd` 且对应阶段合法时启用。`PopupDuelPhase` 的响应值为 Battle `6`、Main2 `2`、End `3` 或 `7`（取决于当前选择窗口）。Minecraft 世界按钮应发送同样的响应值，不能自行修改阶段。

## 对模组的结论

最新版安装包仍然是 Unity 前端 + 原生 `ygoserver.dll`/`ocgcore.dll`，不是适合直接嵌入 Forge 的 Unity 客户端。首版模组应复用标准 TCP 协议，在 Minecraft 服务端运行权威桥接层；先接入本地 ygoserver，验证单人 AI，再实现 Minecraft 双人联机和独立服务器。场上实体、卡组/墓地/额外卡组实体、阶段按钮和临时物品栏都应由已验证的标准消息驱动。
