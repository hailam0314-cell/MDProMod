# 卡堆界面改版：全部卡 + 滚轮 + 两个按钮（2026-10-15）

## 之前的问题

特召额外卡组时只能选到前 3 张。根因在 `PileScreen` 的排版：

```java
x += Math.max(McPanel.CARD_W, 110) + 6;
if (x > panelLeft + panelW - 110) break;   // ← 一行排到第 4 个就 break
```

动作按钮（"召唤：〈卡名〉"）**只画一排、写死最多三个**，而且在 `init()` 里只建一次、**不跟着翻页走**——
所以第 4 张之后连按钮都没有，自然点不到。顺带两个小毛病：按钮上的长卡名会画出按钮外压到隔壁那格上
（截图里那三行字是叠着的），以及"左键看大图"和"点按钮召唤"是两套东西，看的时候分不清哪张能动。

## 现在的界面

```
┌ 额外卡组（15 张）              可以特殊召唤 3 张（金框，排在最前面） ┐
│ 滚轮翻看全部卡 · 左键选中，右键看大图 · 选中后按「特殊召唤」          │
│ ┏金框┓ ┏金框┓ ┏金框┓ [卡图] [卡图] [卡图] …    ← 能召唤的排最前面   │
│ [卡图] [卡图] [卡图] …                          ← 其余按原顺序        │  ▓ 滚动条
│                                                                      │
│ [ 特殊召唤 ]  [ 关闭 ]                                               │
└──────────────────────────────────────────────────────────────────────┘
```

| 操作 | 效果 |
| --- | --- |
| 滚轮 | 上下翻看（右边有滚动条；卡片比视口多时才出现） |
| 左键点卡 | 选中（白框），再点一次取消；选中的卡能召唤时下面「特殊召唤」才可按 |
| 右键点卡 | 弹大图（卡面 + 效果文本，和以前"左键看大图"是同一个界面） |
| 「特殊召唤」 | 把选中的那张特召（墓地 / 除外区这行字是「发动」） |
| 「关闭」 | 关掉界面 |

**能特殊召唤 / 能发动的卡一律排在最前面**，并描一圈**金框**（`McPanel.GOLD`，和界面里其它"可操作"的
强调色一致）；卡图右下角的提示也会写「现在可以特殊召唤」。所以打开就往左上角看，不用翻页找。

## 排序是纯函数

`PileOrder.sorted(actionSeqs, actionCodes, allCodes)`（`PileOrderTest` 12 断言）：

1. 先把**动作里的卡**按"在卡堆里的位置"从前到后放进来；
2. 同一张（序号相同）只留一次；
3. 动作给的序号如果跑到清单外面（比如卡堆顺序和这份清单不一致），**用动作里带的卡号兜底照样排进去**——
   宁可多留一行，也不能再出现"某张卡在界面上根本不存在"这种情况；
4. 其余卡按原顺序跟在后面。

## 额外卡组清单要跟着核心的序号走（同日追加，重要）

用户反馈"召唤完一只怪兽，额外卡组没减少，而且它还能再被召唤一次"。查实机日志坐实了根因：

```
23:05:30  候选：8491961@0 8491961@1 48608796@2 48608796@3 72971064@4
卡组清单：    8491961@0 8491961@1 8491961@2 48608796@3 48608796@4 72971064@5
```

**核心的额外卡组是有序表，卡片离开后序号会整体前移**（清单第三张 8491961 已经召唤掉了，
于是它后面的东西全往前挪了一格）。而界面一直在用**卡组原始清单**（`fieldDecks` 里那份），
于是：①张数永远不变；②`PileOrder` 按"下标 = 序号"把候选贴到卡片上，
**从第二张开始就贴错了**——表现就是"召唤过的怪兽还在列表里、点它还能再召唤（其实唤的是别人）"。

改法：新增 `ExtraDeckTracker`（纯逻辑，`ExtraDeckTrackerTest` 17 断言），维护一份**当前额外卡组**：

| 事件 | 处理 |
| --- | --- |
| 卡片离开额外卡组（融合 / 同步 / 超量 / 连接召唤等） | 去掉**最前面**那个相同卡号（同卡号副本不可区分，核心也是整体前移） |
| 卡片回到额外卡组（表侧灵摆怪被破坏等） | 追加到末尾（核心就是 push_back） |
| 只看自己的（controller 0）那一侧 | 对手的额外卡组、场上 / 墓地 / 手牌的移动一律不算 |

`DuelSessionManager` 在开局时用它初始化（读开局导出的那份 ydk）、每 tick 从
`host.drainEvents()` 的事件里更新、`resetForNewDuel()` 时恢复成整副；
`allCodes(0, 64)` 改成返回这份实时清单（**下标即核心的序号**），
并顺手和核心的 `count(0, 0x40)` 对一下账，不一致就写日志警告（下次再出问题一眼能看到）。
召唤动作本身走的是 `host.promptAction(controller, location, sequence)`——序号对上之后，
点哪张就召唤哪张。
